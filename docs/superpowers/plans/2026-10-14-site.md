# Site de la base de connaissances — plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** publier chaque semaine `kb/` et l'archive des digests en site statique privé
(zensical, Cloudflare Pages + Access), et faire pointer le digest vers ce site.

**Architecture:** un domaine pur (`domain/website/`) calcule un `SitePlan` (pages Markdown et
navigation) à partir des fichiers de `kb/`, des digests rendus en Markdown et du profil.
`website/builder.py` écrit ce plan et un `zensical.toml` dans un dossier temporaire, puis lance
`zensical build`. `SiteStage` lit les stores et relie les deux ; la CLI expose
`auto-biblio site build`. Le déploiement est une étape `wrangler` du workflow du repo de
données.

**Tech Stack:** Python 3.12, uv, Pydantic v2, Jinja2, Typer, zensical (CLI en sous-processus),
pytest, ruff ALL, pyright strict.

**Spec:** `docs/superpowers/specs/2026-10-14-site-design.md`

## Global Constraints

- Règles de `CLAUDE.md` : domaine sans entrées-sorties, modèles Pydantic figés, Protocols,
  docstrings Google, TDD, un module de test par module, couverture de branches ≥ 90 %,
  `make check` vert avant chaque commit.
- Paquets nommés `website` (jamais `site`, qui masquerait le module standard).
- Textes du site en français ; libellés : « Accueil », « Thèmes », « Fiches », « Articles »,
  « Outils », « Billets », « Par thème », « Journal », « Digests », « Cette semaine »,
  « Voir en ligne ».
- Libellés de type : `paper` → « Article », `tool` → « Outil », `post` → « Billet » ;
  profondeur : `short` → « fiche courte », `deep` → « fiche approfondie ».
- Adresses : une page `x/y.md` est servie à `x/y/` ; un digest à `digests/<semaine>/`.
- `config/site.yaml` est optionnel ; sans lui, le digest est strictement inchangé.
- Production : build non strict ; tests : build strict.
- zensical est appelé par `[sys.executable, "-m", "zensical", "build", "-f", <config>]`
  (+ `"--strict"`).
- Version 0.6.0.

## Review Focus

1. **Titre contenant `|`, `[` ou `]`** (fréquent pour les titres d'articles) : les tableaux
   d'index restent valides — `|` est échappé en `\|`, les crochets remplacés par des
   parenthèses dans le texte du lien. Test dans la tâche 5.
2. **Thème de fiche absent du profil** (thème retiré depuis) : la fiche reste listée ; « Par
   thème » ajoute après les thèmes du profil une section par thème inconnu, titrée par son
   identifiant. Test dans la tâche 5.
3. **Base vide** (repo neuf : ni fiche, ni page thème, ni digest) : le site se construit en
   strict ; les index affichent « Aucune fiche pour l'instant. ». Tests dans les tâches 6 et 7.
4. **`site_url` sans barre finale** : normalisé avec une barre finale ; une URL non `https`
   est refusée. Test dans la tâche 1.
5. **Reconstruction dans un dossier `--out` existant** : les fichiers d'un build précédent
   disparaissent (une fiche supprimée ne reste pas en ligne). Test dans la tâche 7.
