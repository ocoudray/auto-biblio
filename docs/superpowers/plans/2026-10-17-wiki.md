# Wiki de connaissances — plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** un wiki de notions validées par PR dans le repo de données, relié chaque semaine aux
fiches de veille par Flash-Lite, publié sur le site avec équations et diagrammes, et rédigé
avec trois skills Claude Code.

**Architecture:** le domaine pur `domain/wiki/` lit et contrôle les pages (`pages.py`,
`check.py`), construit le catalogue et fusionne les liens (`catalog.py`, `links.py`).
`stages/wiki_link.py` étiquette les fiches par lots ; `domain/website/wiki.py` produit les
pages du site ; le builder active MathJax et Mermaid. Les skills et le guide sont des modèles
du scaffold.

**Tech Stack:** Python 3.12, Pydantic v2, PyYAML, Typer, zensical (`pymdownx.arithmatex`,
`pymdownx.superfences`), MathJax 3 (CDN), pytest.

**Spec:** `docs/superpowers/specs/2026-10-17-wiki-design.md`

## Global Constraints

- Règles de `CLAUDE.md` (domaine sans entrées-sorties, modèles figés, Protocols, TDD, un
  module de test par module, couverture ≥ 90 %, `make check` vert avant chaque commit).
- Identifiant de notion : `<domaine>/<notion>`, motif `^[a-z0-9-]+/[a-z0-9-]+$`.
- Rôle LLM `wiki_link`, chaîne `[flash-lite, flash-lite-3.1, gemma]`, lots de `batch_size`
  (20) fiches ; `missing` limité à 3 concepts par fiche.
- Textes du site en français : « Wiki », « Prérequis », « Nouveautés suivies »,
  « Notions », « Notions à couvrir », « à rédiger ».
- Rendu vérifié en amont : `pymdownx.arithmatex` (`generic = true`) + MathJax 3 via
  `https://unpkg.com/mathjax@3/es5/tex-mml-chtml.js` et un fichier de configuration ;
  Mermaid via `pymdownx.superfences` (`custom_fences` nom `mermaid`), rendu natif du thème.
- Les modèles de skills et le guide sont copiés **sans** substitution `string.Template` (ils
  contiennent `$ARGUMENTS`).
- Version 0.7.0.

## Review Focus

1. **Liens vers une notion supprimée ou renommée** (`links.json` contient un identifiant qui
   n'existe plus) : le site l'ignore, aucun lien cassé. Test dans la tâche 6.
2. **Le LLM répond par un titre ou un alias au lieu d'un identifiant** (« Multi-head
   attention » au lieu de `llm/multi-head-attention`) : il est rattaché via l'index des alias
   avant d'être écarté. Test dans la tâche 4.
3. **Un candidat devient une notion** (page créée après coup) : il disparaît des candidats à
   la fusion suivante, même pour les fiches qui ne sont pas réétiquetées. Test dans la tâche 3.
4. **Fiche supprimée de la base mais présente dans `links.json`** : ignorée par le site et
   retirée des liens à la fusion suivante. Tests dans les tâches 3 et 6.
5. **Cycle de prérequis ou page illisible** : `wiki check` le signale ; le site se construit
   quand même (page publiée telle quelle, avertissement). Tests dans les tâches 2 et 6.

### Task 3: catalogue, liens et candidats

**Files:**
- Create: `src/auto_biblio/domain/wiki/catalog.py`, `src/auto_biblio/domain/wiki/links.py`
- Test: `tests/domain/wiki/test_wiki_catalog.py`, `tests/domain/wiki/test_wiki_links.py`

**Interfaces:**
- Consumes: `Wiki`.
- Produces:
  - `CatalogEntry(frozen)` : `id`, `title`, `aliases`.
  - `catalog(wiki: Wiki) -> tuple[CatalogEntry, ...]` (trié par id).
  - `signature(entries: Sequence[CatalogEntry]) -> str` (SHA-256 hex du JSON trié).
  - `normalize(concept: str) -> str` (minuscules, espaces réduits, tirets et `_` → espace).
  - `alias_index(entries) -> dict[str, str]` (titre, alias et id normalisés → id).
  - `NoteLinks(frozen)` : `notions: tuple[str, ...]`, `signature: str`.
  - `Candidate(frozen)` : `name: str`, `notes: tuple[ItemId, ...]`, `first_seen: date`,
    `last_seen: date` ; propriété `count`.
  - `WikiLinks(frozen)` : `notes: dict[ItemId, NoteLinks] = {}`,
    `candidates: dict[str, Candidate] = {}` (clé = nom normalisé).
  - `LinkResult(frozen)` : `notions: tuple[str, ...]`, `missing: tuple[str, ...]`.
  - `stale_notes(note_ids: Iterable[ItemId], links: WikiLinks, sig: str) -> list[ItemId]`.
  - `merge_links(links, results: Mapping[ItemId, LinkResult], *, entries, sig, existing: frozenset[ItemId], today: date) -> WikiLinks` :
    retire les fiches hors `existing` ; pour chaque fiche de `results`, retire sa
    contribution des candidats puis enregistre ses notions (dédoublonnées, triées) ; un
    `missing` qui correspond à `alias_index` devient une notion ; les autres alimentent les
    candidats ; enfin supprime tout candidat dont le nom est dans `alias_index` et tout
    candidat sans fiche.

- [ ] **Step 1: tests** — signature identique quel que soit l'ordre des pages ;
  `normalize("Multi-Head_Attention ")` → `"multi head attention"` ; `stale_notes` (nouvelle
  fiche, signature changée, à jour) ; fusion : candidat compté une fois par fiche, `missing`
  égal à un alias → lien ; **candidat devenu notion supprimé même sans réétiquetage** ;
  **fiche supprimée retirée** ; réétiquetage qui retire un candidat de sa fiche.
- [ ] **Step 2:** FAIL. **Step 3:** implémenter. **Step 4:** PASS.
- [ ] **Step 5:** commit `feat(wiki): catalog, links and candidates`.

  - `note_page(..., notions: Sequence[tuple[str, str]] = ())` : ligne `> Notions : …` (titre,
    chemin relatif depuis la fiche) sous la ligne de métadonnées.
